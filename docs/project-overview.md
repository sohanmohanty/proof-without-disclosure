# Project overview: Proof Without Disclosure

## The central question

How can mathematics let people prove, verify, or trust something without
revealing private information?

## Why cryptography

Most software answers "how do we compute this faster?" Cryptography answers
a stranger and more social question: how do people who do not trust each
other cooperate anyway? Its answers are not policies or promises; they are
mathematical objects whose misuse is not forbidden but *infeasible*. That
inversion (trust as a theorem, not an assumption) is the intellectual pull
of this project.

## Why privacy-preserving proof, specifically

Encryption gets the headlines, but the deeper primitive is proof:

- "This file is exactly what it was yesterday." (integrity)
- "I predicted this before it happened." (commitment)
- "My name is on the approved list you can't see." (membership)
- "I wrote this message." (authenticity)
- "I know the secret, and you may not have it." (zero-knowledge)

Each is a claim someone can *check* without the claimant surrendering
anything beyond the claim itself. The project's theme, trust without
exposure, is the thread connecting all five.

## What the website teaches

Six interactive modules in a deliberate arc: hash functions → commitments →
Merkle trees → signatures → zero-knowledge (graph coloring) → the Schnorr
protocol. Each module follows the same discipline: plain-English question
first, interaction second, formal names third, pseudocode fourth, and an
explicit list of what the primitive does **not** guarantee. Every module has
a "try to cheat" mode, because soundness and binding only become real when
you watch cheating fail. The arc lands on one unifying insight: a digital
signature is a zero-knowledge proof of key knowledge made non-interactive by
a hash function.

## What the toolkit does

`prooflab` is a Python CLI that generates and verifies the same objects
locally: file hashes, commitments and reveals, Merkle trees and membership
proofs, ECDSA signatures, Schnorr proofs, and a zero-knowledge coloring
simulation. It shares no code with the website (only a byte-level format
spec and a pinned set of test vectors), so proofs cross between terminal and
browser in both directions. The core uses only the Python standard library
and is meant to be read.

## Current implementation

The built project has two independent implementations of the same proof
formats:

- `website/`: React + TypeScript, client-side cryptography, clean URLs, and
  a static Vite build with a pre-built HTML page and sitemap entry for every
  lab.
- `prooflab/`: installable Python CLI with commands for hashing,
  commitments, Merkle trees, signatures, Schnorr proofs, and graph-coloring
  simulations.
- `docs/format-spec.md`: byte-level interoperability rules.
- `vectors/test-vectors.json`: shared vectors generated by Python and checked
  by both test suites.
- `.github/workflows/ci.yml`: CI for Python tests, website tests,
  type-checking, and production build.

Current verification coverage: 61 Python tests and 62 TypeScript tests.

## Success criteria

A curious high-school student can explain a Merkle proof after twenty
minutes on the site; a technical reader finds real substance (RFC 6962
domain separation with the attack it prevents, soundness bounds plotted
live, an extraction argument you can execute); and every artifact is honest
about being educational rather than production security software.
